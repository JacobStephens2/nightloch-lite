## Conventions this thread established

Not written down anywhere else. Worth continuing.

**Verify external claims before asserting them.** The highest-value findings came from reading primary sources, not from recall — AdGuard Home v0.107.78 source, AOSP `DnsManager`/`Vpn.java`, the WireGuard Android/Apple clients, Chromium and Gecko DoH logic, DO/Caddy/Cloudflare docs. Four findings contradicted things the project documents treated as settled fact. Citations are in [plan/adversarial-review.md](../plan/adversarial-review.md) § *Appendix — verified facts and citations*, including an explicit "not verified — test these yourself" list. **Consult that appendix before re-researching.**

**Prove code findings by running them.** The Slice 0 DST bug (S1) was demonstrated with a throwaway probe test that showed the predicate returning "allowed" where the brute-force oracle returned "loosening" — then the probe was deleted and `git status` confirmed clean. Assert defects with a reproducing case, or label them as unverified.

**Scope findings honestly.** S1's writeup includes the negative result (400 random same-timezone pairs found nothing) alongside the positive one. T3 says outright that dpkg conffile behavior could not be tested without a Linux host. Overclaiming costs more credibility than an admitted gap.

**Use the glossary.** [CONTEXT.md](../CONTEXT.md) is authoritative for product vocabulary — Protectee, Partner, Partnership, Roster, Device, Policy, Curfew, Coverage, Operator. It has explicit *Avoid* lists. Code identifiers still lag (`SubjectMayApplyEdit`, `subject_user_id`); prefer Protectee in new names.

**One recurring theme across all four reviews:** the product's failure modes default to *silent fail-open* — a blackhole described as fail-open (F1), a baseline with no tamper detection (F3), validators that exist but are never called (S3). The Slice 0 review proposed a standing convention — *invalid or unknown state denies the edit and raises an alert, never silently permits* — which has **not** yet been written into [docs/SECURITY-POLICY-DESIGN.md](./SECURITY-POLICY-DESIGN.md). Worth doing before Slice 2 adds handlers that each face the choice independently.

## Secrets and redaction

**This document contains no credentials, and none were exposed in the session.**

- Real API tokens were never handled by the agent. `docs/SECRETS.md` documents *how* to obtain DO/CF/Resend credentials; it holds no values.
- `status.md` carries non-secret Bitwarden Secrets Manager metadata (project name, project UUID, machine-account name, token expiry). It is deliberately **not** restated here. Treat the UUID as an infrastructure identifier, not a secret, but there is no reason to copy it into new files.
- `random_password.console` (the droplet console/recovery password) exists only in OpenTofu state. **Never run `tofu output -raw console_password` into a transcript, log, or file.** T5/T6 cover the consequences: DO account access implies root, and state is currently local and unbacked-up.
- `scripts/slice1-up.sh` is written to avoid printing secret values. Preserve that property in any edit.
- `docs/BITWARDEN_BROWSER_AGENT.md` is gitignored. The two new `*_TOKEN_BROWSER_AGENT.md` files are untracked and were scanned — no secret-shaped strings — but decide deliberately whether they belong in git before committing.
